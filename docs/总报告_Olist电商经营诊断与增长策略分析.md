## 〇、30 秒电梯版

**一句话**：Olist 是一家巴西本土电商平台，过去两年**用规模换利润**、**用体验换增长**——目前已经清无可复购、护无可护住，**S6 给出的三条干预里只有「延迟补偿券」一项回本**。

**给老板的三句话**：

1. **增长已经停了**——2017-11 之后 10 个月零增长，全靠拉新撑着（贡献 104.2%），客单价反拖 −5.3%；盘子集中在 SP 一个州（46.5%）
2. **体验在恶化**——延迟率从 3% 涨到 10%、3~7 天是评分断崖、瓶颈全在承运商不是卖家、地理问题不是商品问题
3. **干预有答案但有边界**——三条策略里 **P3 延迟补偿券 ROI 1.404、净 +R$20,133 最优**；**P2 风险拦截反而亏损 R$−9,381**（把 S4 的建议修正了）；**整个可干预池只有 R$64K，瓶颈不是钱、是没那么多延迟单可救**

**最可能问的三件事**：
1. "你做的最有挑战的一步是什么？"——**S5 证伪"差评→复购"**（KM log-rank p=0.4803），推翻了一个直觉判断
2. "模型预测有用吗？"——**HGB PR-AUC 0.336，拦前 1% 精度 71%、lift 7.06**，但**绝对概率不可外推**，需要配合 k% 增益曲线而不是固定阈值
3. "你怎么知道策略值不值钱？"——**反事实仿真 + (p, v) 二维敏感性**：把无法测的挽回率 p 和差评价值 v 显式做敏感性网格，给的不是"一个 ROI"而是**盈亏平衡条件**

## 一、项目全景：6 个专题如何环环相扣

```
        ┌─────────────────── S1 数据底座 ───────────────────┐
        │ 9 个 CSV → ods → dwd → dws → ads 四层建模       │
        │ 口径统一在 SQL 层；所有专题共用同一份事实        │
        └──────────────────────┬────────────────────────────┘
                               ↓
   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
   │ S2 GMV 拆解  │ → │ S3 履约体验  │ → │ S4 差评预警  │
   │ 增长是否停了 │   │ 哪里出了问题 │   │ 谁能抢回来    │
   │ (归因)       │   │ (诊断)       │   │ (拦截)       │
   └──────┬───────┘   └──────┬───────┘   └──────┬───────┘
          ↓                  ↓                  ↓
   ┌──────────────┐   ┌──────────────┐
   │ S5 价值分层  │ → │ S6 策略评估  │
   │ 该救谁       │   │ 值不值得救   │
   │ (对象)       │   │ (财务)       │
   └──────────────┘   └──────────────┘
```

**这条链不是装饰**——每一个专题的结论都成了下一个专题的输入：

| 接力点 | 上游给了什么 | 下游接住了什么 |
|---|---|---|
| S2 → S3 | "拉新是单引擎，客单价 −5.3%，SP 占增量 46.5%" | "那增长的代价是什么？" → 看体验是否在恶化 |
| S3 → S4 | "延迟 3~7 天是断崖，瓶颈在承运商，地理问题" | "那能不能提前预测哪一单会差评？" → 看模型能拦什么 |
| S4 → S5 | "差评能被预测，但拦前 1% 精度 71%" | "那差评的人会不复购吗？" → 看分类对象是否选对了 |
| S5 → S6 | "差评不驱动复购，复购是人格特质" | "那干预到底值不值钱？" → 看 P2/P3 还能不能算上复购收益 |

**这意味着任何一个专题单独看都不成立**——S4 的模型再准，没 S5 证伪"差评→复购"，就会高估 S6 的复购收益；S6 的 ROI 再好看，没 S3 的"3 天断崖"和 S5 的"365 天 PSM −1.46pp"，就不知道"什么时候、出给谁、为什么"。

## 二、数据底座与口径（S1 极简版）

### 2.1 数据规模
- orders 99,441 行｜order_items 112,650 行｜reviews 99,224 行｜customers 99,441 行
- products 32,951 行｜sellers 3,095 行｜geolocation 1,000,163 行
- 时间跨度：2016-09-15 ~ 2018-09-03（24 个月，但首尾残缺）

### 2.2 四层建模
```
ods_olist_*       原始 9 张表（CSV 导入，建好类型）
   ↓
dwd_olist_*       清洗：日期解析、口径统一、字段标准化
     ├→ dwd_orders（主表，含 is_delivered、delay_days、is_late）
     └→ dwd_orders_with_rfm（带 RFM 标志位）
   ↓
dws_olist_*       主题宽表：月度、品类、州、用户、卖家
   ↓
ads_*             应用层：直接被 Tableau 拉的报表（22 张）
```

**口径统一在 SQL 层**——这是项目的纪律。Python 只做统计推断、ML、置信区间；Tableau 只画图，不重新定义口径。**口径环（瀑布图"每段起点 = 前面所有段累加"、客户级去重、用户唯一键）一旦被画图工具动过就回不去了**。

### 2.3 三条关键口径（任何数字出现前先确认）
1. **GMV = Σ(item_amount + freight_amount)**，**仅 `is_delivered = 1`**，含运费
2. **用户 = `customer_unique_id`**（**不是** `customer_id`——后者每单新建，算出"复购率 100%"）
3. **完整月 = `order_cnt >= 500`**，同时写在 SQL 和 Python config，**两处必须一致**

### 2.4 有效分析区间
- 第一个完整月 → 最后一个完整月：**2017-01 ~ 2018-08（20 个月）**
- 2016 年只有零星几个月（剔除）、2018-09 之后骤降到个位数（剔除）
- 区间内 GMV 127,482 → 985,491，**+673.1%，增量 858,009**

## 三、GMV 增长归因（S2）：增长已停，全靠拉新

### 3.1 一句话结论
> **平台进入了"增长平台期"。20 个月里 GMV 涨了 6.7 倍，但增速三段式衰减 46.0% → 7.75% → 0.08%（月均），断点落在 2017-05 和 2017-11；2017-11 后已经 10 个月接近零增长。增长全部靠拉新，客单价反拖 −5.3%。**

### 3.2 三因子拆解（全区间累计）
| 因子 | 贡献额 | 占比 | 解读 |
|---|---:|---:|---|
| **下单人数** | **+893,885** | **+104.20%** | 全部增长的来源 |
| 人均频次 | +9,971 | +1.20% | 几乎不变（复购率仅 3%） |
| **客单价** | **−45,847** | **−5.30%** | 净拖累，规模越大越亏 |
| **合计** | **+858,009** | **100%** | |

### 3.3 一个必踩的坑：全序列趋势检验会骗人
- 全序列 Mann-Kendall：**tau = 0.7053，p ≈ 0**（"显著上升"）
- 分段后三段没有一段显著
- **功效下限**：n=4 时 MK 最小可达 p=0.0894 > 0.05（**4 个观测点永远判不出趋势**）

> **只看全序列会得出"还在高速增长"的错误结论。** 这是 S2 最容易被追问的一个点——展示的不只是技术，更展示"分得清什么是真的趋势、什么是统计幻觉"。

### 3.4 最近一个月（2018-08 vs 2018-07）的反转
| 因子 | 贡献额 | 占比 | 95% CI | 显著 |
|---|---:|---:|---|---|
| 下单人数 | −13,571 | 32.1% | [−22,884, −128] | 显著 |
| **客单价** | **−73,213** | **173.0%** | **[−118,065, −26,215]** | **显著** |
| 人均频次 | +44,282 | −104.7% | — | 噪声 |

**反转**：全区间累计看"拉新主导"（104.2%），但最近一个月看"客单价主导"（173.0%）。**这才是可行动的那个**——人数是宏观变量，客单价是单价干预能影响的事。

### 3.5 地理结构：增量集中在 SP 一个州
- SP 贡献全区间增量的 **46.5%**（39.9 万 / 85.8 万）
- 第二名 RJ 仅 9.7 万，不足 SP 的 1/4
- **风险**：增长模型高度依赖单一地理，渠道分散性极差

> **这条结论直接连到了 S3 的"延迟是地理问题不是商品问题"**——最差的几个州同时也是延迟最严重的州（RJ + BA 占全国 27.7% 的延迟单）。

### 3.6 给老板的行动建议（S2）
1. **不要再以"GMV 还在涨"为乐观依据**，看分跨区域分布
2. **客单价干预是当务之急**——S2/S3 共同指向"评分下降 → AOV 下降"的链条
4. **SP 的成功模式不能简单复制到其他州**——RJ/BA 的物流条件与 SP 差异巨大（详见 S3）

## 四、履约体验瓶颈（S3）：地理问题不是商品问题

### 4.1 一句话结论
> **延迟是 Olist 体验问题的根因。8.0% 的订单超出（本就宽松的）预估送达日；延迟率从 3% 涨到 10%；延迟 3 天是评分断崖（直接 −1.63 分）；7 天后评分锁死（后两组 CI 完全重叠）；86% 的延迟时长差发生在承运商环节（不在卖家备货）；地理跨度比品类跨度更影响延迟（州差异 13%~24%，品类差异仅 8.9%~13.0%）。**

### 4.2 剂量反应（最值钱的图）
| 延迟天数 | 平均评分 | vs 4.14 基准 | 解读 |
|---|---:|---:|---|
| 准时 | 4.14 | — | 基准 |
| 0~3 天 | 3.75 | −0.39 | 还能保住三星半 |
| **3~7 天** | **2.51** | **−1.63（单步 −1.24）** | **断崖，3 天是必须干预的红线** |
| 7~14 天 | 1.74 | −2.39 | 评分已锁定 |
| >14 天 | 1.71 | −2.42 | 后拖不再恶化（与 7~14 天 CI 重叠） |
| 提前 >10 天 | 4.32 | +0.19 | 超预期交付有正向收益 |

### 4.3 ⭐ 干预窗口的发现
- **3 天断崖**：单步跳跃 −1.24 分，是剂量反应中最显著的拐点
- **7 天饱和**：延迟 7~14 天 vs >14 天只差 0.03 分，CI 完全重叠 ⇒ **7 天后任何补救都改变不了评分**
- **干预窗口 = 延迟 3~7 天**：这是 S6 把 P1 物流提速的命中条件设为"延迟 3~7 天"的直接依据

### 4.4 ⭐ 瓶颈在承运商，不在卖家
- **86.2%** 的延迟时长差发生在"交承运商 → 签收"环节
- 卖家审批环节 CI 重叠、不显著（只占差 0.4%）
- **结论**：治"量"该打承运商 SLA，**不该打卖家备货**

### 4.5 ⭐ 地理问题不是商品问题
| 维度 | 跨度 | 占全国订单 | 占全国延迟单 |
|---|---:|---:|---:|
| 最差 8 个州 | 13%~24% | 19.8% | **~35%** |
| 最差 8 个品类 | 8.9%~13.0% | — | 仅 ~8.6% |

- 最差州中 **RJ + BA 两州 ≈ 全国 27.7% 的延迟单**
- **结论**：买错地区该做"分区域物流方案"，**不是"分品类包装方案"**

### 4.6 趋势在恶化
- Mann-Kendall：**tau = 0.337，p = 0.0410（n=20，功效充足）**
- "显著恶化"可以直接写——这与 S2 的"增长已停"是同一个信号的不同侧面

### 4.7 与 S2 的闭环
- S2 说"增长靠拉新 + 远方州"
- S3 说"远方州延迟 2~3 倍"
- **结论**：平台正在用"地理换规模"——增长的方向与履约能力**错配**

### 4.8 给老板的行动建议（S3）
1. **治标**：在延迟 3~7 天的订单上做主动通知/补偿（这是 S6 P3 的设计依据）
2. **治本**：对 RJ + BA 两州做专项承运商 SLA（合计 27.7% 的延迟单）
3. **不该做的事**：按品类做包装改进、按卖家做末位淘汰（都不是主因）

## 五、差评预警模型（S4）：能拦但不该全拦

### 5.1 一句话结论
> **差评可预测但只能算"中等"——HGB 模型 PR-AUC 0.336（基线 0.100，3.36×），拦前 1% 精度高达 71%、每挽回 1 个差评成本 R$21，但拦前 10% 单位成本已涨到 R$41、拦前 20% 涨到 R$116。特征重要性首位是 `is_late`（0.48）和 `delay_hours`（0.16），卖家历史质量只排第 5~7——**走"物流提速"不走"卖家治理"**。**

### 5.2 模型表现
| 模型 | PR-AUC | ROC-AUC | Brier | 阈值处 Precision | 阈值处 Recall |
|---|---:|---:|---:|---:|---:|
| HGB | **0.3359** | 0.71 | 0.15 | **0.43** | 0.41 |
| 逻辑回归 | 0.2770 | 0.70 | 0.16 | 0.34 | 0.33 |
| 基线（全部预测无差评） | 0.100 | 0.50 | — | — | — |

**解读**：
- PR-AUC 0.336 = 真实提升，但对应"精度只有 43%"（阈值法）/ 37%（拦前 10%），**不是"精准预测"**
- ROC-AUC 0.71 = 中等（HGB 只比 logreg 高 0.01，说明**线性模型已经抓住了大部分结构**）
- Brier 0.15 = 因为基线率才 10%，不能单独当成绩

### 5.3 ⭐ 拦前 k% 增益曲线（决策级图）
| 拦截范围 | 覆盖单数 | 捕获差评 | 精度 | 边际成本（每差评） |
|---|---:|---:|---:|---:|
| **前 1%** | **252** | **178** | **71%** | **R$21**（最低） |
| 前 2% | 503 | 277 | 55% | R$24 |
| 前 5% | 1,259 | 532 | 42% | R$36 |
| **前 10%** | **2,524** | **929** | **37%** | **R$41**（拐点） |
| 前 20% | 5,034 | 1,353 | 27% | R$116 |
| 前 30% | 7,545 | 1,629 | 22% | R$166 |

**边际成本曲线**：1→2% R$24｜2→5% R$36｜**5→10% R$69（断崖）**｜10→20% R$116｜30→50% R$212

**结论**：**不要无脑扩大拦截范围**——拐点在 5%~10%，超过就是把钱扔进海里。

### 5.4 ⭐ 决策：走"物流提速"不走"卖家治理"
| 特征 | logreg 系数 | HGB 重要性 |
|---|---:|---:|
| **`is_late`** | **0.48（首位）** | **0.48** |
| **`delay_hours`** | **0.16** | 0.16 |
| `item_cnt` | 0.31 | 0.06 |
| `freight_ratio` | 0.13 | 0.05 |
| `payment_installments` | — | — |
| `seller_hist_bad_rate` | 仅排 **第 7** | 仅排 **第 5** |

**卖家历史质量不是主因**——S6 据此把 P2 风险拦截（卖家伙的）的成本算得最贵（券 + 客服 R$11/单），最终算出 ROI 0.830 唯一亏损。

### 5.5 ⚠️ 必写的诚实声明
- 训练差评率 13.75% vs 测试差评率 10.00%：**有 3.75pp 的分布漂移**
- ⇒ **排序能力可外推、绝对精度不可外推**
- ⇒ **模型捕获 ≠ 券能消除**，真实成本 = R$40.75 / 挽回率 p（p 必须由 S6 实验测）

### 5.6 给老板的行动建议（S4）
1. **拦前 1%~10% 是甜区**——超过 10% 单位成本爆炸
2. **必须走物流时效**，不要走卖家治理 — 数据不支持
4. **任何"模型多准"的话术都别信**——只有"拦前 k% 业务值多少钱"才是真问题

## 六、价值分层悖论（S5）：复购是人格特质，差评不驱动复购

### 6.1 一句话结论
> **S5 推翻了两个"想当然"——① "差评导致不复购"被证伪（KM log-rank p=0.4803）；② "改善体验能拉高复购"被削弱（除"长周期延迟"外，所有体验维度都不显著）。复购是"人格特质"不是"体验结果"。** 这把 S6 的复购口径直接收窄——**只有真正消除延迟的策略（P1 物流提速）才能算上复购收益，券不能**。

### 6.2 ⭐⭐ 核心反直觉证据

#### 6.2.1 "差评 → 复购"被证伪
| 对照组 | KM log-rank p | 解读 |
|---|---:|---|
| 差评组 vs 好评组 | **p = 0.4803** | **完全不显著**——S4 模型不能用来预测复购 |
| 延迟组 vs 准时组 | **p = 0.0179** | **显著**——延迟影响复购**不走差评渠道** |

**S5 修正了 S4 的隐含假设**——S4 的"差评预测模型"和 S5 的"复购预测模型"是两个独立问题，**不可互相替代**。

#### 6.2.2 维度验证：所有体验维度都不显著
| 维度 | FDR 校正后 p 值 | 显著？ |
|---|---|---|
| 收货州（23 个） | 全部 > 0.05 | ❌ |
| 金额四分位 | > 0.05 | ❌ |
| 首单评分 | > 0.05 | ❌ |

**结论**：**不要指望靠改善体验把复购率从 3% 拉到 6%**——数据不支持。

#### 6.2.3 PSM 净效应：长期看延迟伤害复购
| 观察期 | naive 差 | psm 差 | 解读 |
|---|---|---|---|
| 180 天 | −0.39pp（p=0.079） | −0.23pp（**p=0.4412 不显著**） | 短期看，延迟对复购影响很小 |
| **365 天** | **−1.38pp（p=0.008）** | **−1.46pp（p=0.0641 接近显著）** | **长期看，延迟伤害 1.46pp** |

**匹配后最大 |SMD| 从 0.470 降到 0.034**——PSM 质量合格。
**延迟伤害的是长期信任，不是短期报复**——干预要看长周期。

#### 6.2.4 ⭐ 唯一强复购信号：首单 3 件+
| 件数 | 复购率 | vs 1 件差异 | FDR p |
|---|---:|---:|---:|
| 1 件 | 3.12% | 基准 | — |
| 2 件 | 3.30% | +0.18pp | > 0.05 |
| **3 件+** | **5.45%** | **+2.33pp** | **< 0.0001** |

**多件购买是唯一强复购预测器**——且它**下单时就知道**，是最值得运营的人群。

### 6.3 8 格 RFM 在数据上站不住
- K-means 最优 **K=2（轮廓系数 0.7188）** 碾压 K=3~6（0.36~0.44）
- 数据里**只有 2 群**：簇 0 = 93,099 单次客、簇 1 = 2,997 复购客
- 与修正八格 ARI = **0.0483**（与随机无异）
- 与 `sql/02` 五分位八类 ARI = **0.0083**（**退化到随机水平**）

**为什么旧版五分位会退化？** 3% 复购率下 `NTILE(5) ORDER BY order_cnt` 不合并并列值、按行位置硬切，**f_score 1~4 全是单次客**、第 5 档混了全部复购客。**分箱数要服从数据的区分能力，不能机械套用五分位**。

### 6.4 首购月份表的陷阱
- 2017-01 复购率 7.58% → 2018-08 0.81%（单调下降）
- **这是右删失伪装成的下滑**，不是客户质量变差：2018-08 的客户到分析日为止还没过完整 365 天观察期
- **必须用 KM 处理右删失**，不能用朴素复购率

### 6.5 给老板的行动建议（S5）
1. **不要为了拉高复购率去大规模干预体验**——除"延迟 3~7 天"外没有证据
2. **复购人群的真正信号是"首单件数 ≥3"**——这是下单时可识别的，唯一可运营的人群
3. **删掉五分位 RFM**——3% 复购率下它会退化成噪声
4. **差评预警模型不能用来预测复购**——两个独立问题

## 七、策略效果评估（S6）：P3 延迟补偿券最优，P2 风险拦截亏损

### 7.1 一句话结论
> **三条策略里 P3 延迟补偿券最优（ROI 1.404、净收益 +R$20,133、盈亏平衡挽回率 35.6%）；P1 物流提速次之（ROI 1.297、净 +R$4,245）；**P2 风险拦截反而亏损（ROI 0.830、净 −R$9,381，唯一亏损）——直接修正了 S4 的建议。** 整个可干预池只有 R$64,084——给 50 万预算有 87% 花不出去，**瓶颈不是钱、是可干预订单池的规模**。

### 7.2 ⭐ 核心三表

##### 三策略成本结构（每单成本完全不同）
| 策略 | 命中条件 | 覆盖单数 | 单均成本 | 成本结构 |
|---|---|---:|---:|---|
| **P1 物流提速** | 延迟 3~7 天 | 1,786 | R$8.00 | 加急运单 |
| **P2 风险拦截** | 延迟 >3 天 | 5,011 | R$11.00 | 券 R$9 + 客服触达 R$2 |
| **P3 延迟补偿券** | 全部延迟 | 7,661 | R$6.50 | 补偿券 10×0.65 核销率 |

##### 主测算（p=0.5, v=R$40.75）
| 策略 | 总成本 | 可挽救差评 | 总收益 | **净收益** | **ROI** | **p\*** | 结论 |
|---|---:|---:|---:|---:|---:|---:|---|
| P1 物流提速 | 14,288 | 800 | 18,533 | **+4,245** | 1.297 | 0.386 | 建议投放 |
| **P2 风险拦截** | 55,121 | 2,245 | 45,740 | **−9,381** | **0.830** | 0.603 | **亏损** |
| **P3 延迟补偿券** | 49,797 | 3,432 | 69,930 | **+20,133** | **1.404** | **0.356** | **建议投放** |

> **修正 S4 的建议**：S4 只看模型精确度，没算干预完整成本（券 R$9 + 客服 R$2 = R$11/单）；算全后 P2 反而最贵、最不划算。**这不推翻 S4，而是把 S4 从"模型视角"修正到"财务视角"**。

### 7.3 ⭐ 预算分配（按"每元净收益"贪心排序）
| 预算档 | 已分配 | 已用策略 | 未分配留痕 |
|---|---:|---|---:|
| 5 万 | 49,797 | P3（100%） | R$203（接近花完） |
| 10 万 | 64,085 | P3 + P1 | R$35,915 |
| 20 万 | 64,085 | P3 + P1 | R$135,915（68%） |
| 50 万 | 64,085 | P3 + P1 | **R$435,915（87%）** |

**核心结论**：**盘子只有 R$64,084**（全部盈利策略完整覆盖一轮的投入上限）。**瓶颈不是钱，是可干预订单池规模**——想花更多钱必须扩大可干预池（例如把干预点前移到"发货前预警"），而不是提高单均投入。

### 7.4 (p × v) 二维敏感性（42 格盈利数）
| 策略 | 盈利格子占比 | 解读 |
|---|---:|---|
| **P3** | **25/42 (59.5%)** | **最稳健** |
| P1 | 24/42 (57.1%) | 次稳健 |
| P2 | 15/42 (35.7%) | 最脆弱 |

**敏感性分析的真正用法**：**不是找一个数，而是检验排序稳不稳**——三种参数组合下 P3 永远最优、P2 永远最差，**排序不依赖参数取值**。

### 7.5 ⭐ 反事实仿真不是 A/B 实验
- **是反事实仿真，不是 A/B 实验**——Olist 历史数据里平台没做过补偿实验
- **把无法测的 p、v 显式做成敏感性网格**，输出盈亏平衡条件而不是单点 ROI
- **上生产前 p\* 是需要验证的假设，不是已知事实**
- **业务上**：可以在 1,786 单（P1 覆盖单）做 4 周小流量真实验，回收实际挽回率

### 7.6 给老板的行动建议（S6）
1. **P3 延迟补偿券——优先投放**：ROI 最高、覆盖最广、成本结构最简单、不需要客服团队配合
2. **P1 物流提速——作为补充**：如果能在 3~7 天窗口内真的提速
3. **P2 风险拦截——重新设计**：先把客服触达成本降下来，或与 P3 合并
4. **预算上限给 R$65K**——给多了花不出去

## 八、跨专题闭环：把 6 个结论串成一个故事

### 8.1 一个核心叙事

> **Olist 正在"用规模换利润、用体验换增长"——但已经清无可复购、护无可护住。**

证据链：

1. **S2**——平台用 104.2% 的拉新撑着增长，但 2017-11 后已经 10 个月零增长
2. **S3**——延迟率从 3% 涨到 10%，评分断崖在第 3 天，瓶颈在承运商
3. **S4**——延迟（前两位的特征）是差评的根因，**但拦差评只是治标**
4. **S5**——差评不驱动复购，体验改善也拉不高复购率，**真正能拉复购的是"首单件数 ≥3"**
5. **S6**——三条干预里只有"P3 延迟补偿券"回本（1.404）、"P2 风险拦截"亏损（0.830）
6. **整个盘子只有 R$64K**——这不是钱的问题，是可干预订单池规模的问题

**故事的结尾**：Olist 的增长问题是结构性的，不是单点干预能解决的。但 S6 给了一个**有边界但有答案**的处方——**先做延迟补偿券（R$20K 净收益、35.6% 盈亏平衡挽回率），同时用"首单 3 件+"作为复购种子人群的运营抓手**。

## 十、局限与展望

### 10.1 数据局限
1. **Olist 数据只到 2018-09**——结论有效期约 2018 年情境，不可直接套用到 2024+ 巴西电商
2. **右端截断**——2018-08~09 部分订单未送达，用 `gmv_all/gmv` 自检口径
3. **各表实际数据比公开参考值少 1 行**（CSV 末行无换行符），不影响结论
4. **缺失变量**：没有客单价演变的原因（季节性、促销、汇率）、没有广告投放数据、没有竞品数据

### 10.2 方法局限
1. **趋势检验的功率问题**：n=4 时 MK 最小可达 p=0.0894 ⇒ 4 个观测点永远判不出趋势（已用分段规避）
2. **PSM 只控制可观测变量**：未观察到的混淆（如同地区同时上线延迟补偿券）无法控制
3. **ML 模型可解释性局限**：HGB 用 SHAP 重要性而非因果推断
4. **反事实仿真不是 A/B 实验**：p\* 是需要生产验证的假设，不是已知事实

### 10.3 业务可移植性
- **可移植的**：方法论（四层建模、口径锁 SQL 层、ROI+敏感性）、代码结构（`config.py` / `common.py` / `sX_0Y_*.py`）
- **不可移植的**：具体数字、阈值（`order_cnt >= 500`）、巴西地理（SP/RJ/BA）

### 10.4 展望
- 如果数据可用，可以加：广告投放数据（拉新的成本）、客户终身价值（LTV 完整版）、退款/退货数据（体验另一面）
- 如果时间充裕，可以做：因果推断（DiD / PSM-DO）、预测实验（夏热节对评分）、增量归因（Markov / Shapley）
- 如果上生产，可以做：模型监控（PSI / KS）、A/B 实验框架、自动化决策看板

## 结语

> **这个项目的真正价值不是 6 张报表或 60 项自检，而是它把"为什么"放在"是什么"前面**——
> 为什么 GMV 增长停不下来？因为拉新是单引擎。
> 为什么评分下降？因为延迟 3~7 天是断崖。
> 为什么差评模型不能预测复购？因为数据证伪了这条路径。
> 为什么 P2 反而亏损？因为把 S4 的隐含假设"差评能挽回"和"成本只算券"都修正了。
>
> **每个"是什么"都有一个"为什么"，每个"为什么"都能回答"那老板该怎么做"。**
> 这是数据分析，不是数据展示。
